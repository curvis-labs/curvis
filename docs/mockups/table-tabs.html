Curvis table tabs

A project holds several tables, each in its own tab inside the project tab. The Results and Graph panels stay at the right and show the analyses and graphs of the table that is selected. Versions A to D differ only in where the table tabs sit; boards 5 to 8 apply to all of them. Orange numbers point to the notes.

A · Sheet tabs along the bottom, like a spreadsheet

  1. Table tabs under the table and the side panel, as in Excel, LibreOffice and Prism. The selected tab joins the table above it.
  2. + at the end of the row is New table (Ctrl+Shift+N).
  3. Each tab has a close button. Closing deletes the table, after a warning (board 6).

Familiar to anyone who uses a spreadsheet; the two rows of tabs never sit next to each other.

The table gets the full height under the toolbars.

Far from the toolbar and the project tabs, so it is easy to miss which table Import data or Analyze will act on.

B · A second tab row on top, under the project tabs

  1. Project tabs (unchanged) above, table tabs under them across the full width. The table tabs are flat with a teal line under the selected one, so the two rows do not look the same.
  2. A small table icon in front of each name says these are tables.
  3. + is New table.

Reads top-down: project › table › its data and results. The table that Import data acts on is right under the toolbar.

The side panel is visibly inside the selected table, which matches “analyses and graphs belong to their table”.

Two rows of tabs take about 32 px more height.

C · Table tabs above the table only; the side panel keeps its own tabs

  1. The table tabs sit over the table column only. The Results / Graph tabs share the same row at the right.
  2. + is New table.

No extra row: the same height as today.

Table tabs and Results / Graph tabs look alike and sit side by side, so it is less clear that the side panel changes with the table.

Many tables run out of room sooner, because the row is only as wide as the table.

D · Vertical tabs at the left

  1. A list of tables at the left edge, with the number of analyses and graphs of each table beside its name. The close button shows on hover.
  2. + in the list's header is New table.

Long names and many tables fit without scrolling sideways.

Takes about 170 px of width from the table, on top of the 300 px side panel.

Looks like a project tree (Prism's navigator), which may suggest that graphs and analyses can be listed there too.

5 · New table: File menu, main toolbar and Ctrl+Shift+N (shown with version B)

  1. New table in the File menu, right under New project, with Ctrl+Shift+N (not used yet, and not a platform standard key). It is also in the command palette.
  2. In the main toolbar, next to New project: a table with a teal plus, the same two tones as the other icons. Tooltip “New table (Ctrl+Shift+N)”. It is in the main toolbar rather than the table toolbar, because the table toolbar hides when the project has no table (board 8).
  3. Close table… asks first (board 6). Ctrl+W keeps closing the project; its menu text becomes “Close project” so the two are told apart.

The new table is named “Table 2”, “Table 3” …, added after the selected tab and selected. One undo step.

Import data always goes into the selected table, as now. The status bar names it: “Imported 96 rows and 4 columns from plate.csv into Viability.”

6 · Closing a table deletes it, after a warning

  1. Window title names the task: “Close table”. The first line says what happens to what.
  2. What else goes with it: its analyses and graphs (they belong to the table). A table with nothing attached gets only the first line.
  3. Undo is one step (Ctrl+Z), and is said, so the warning does not feel final.
  4. The verb button is Delete table. Cancel has the default focus, so Enter does not delete by accident.

Closing an empty table (no data, no analyses, no graphs) does not ask.

If a calculated column in another table reads this table, the dialog says so and lists it, and those columns show their error until the table is restored.

7 · Tab menu and renaming (shown with version B)

  1. Double-click a tab to rename it in place. Enter keeps the name, Esc cancels. A name that is taken shows a message in the status bar and keeps the old name.
  2. Right-click: Rename, Close table…, New table. Tabs can be dragged to change their order.
  3. Ctrl+Page Down and Ctrl+Page Up go to the next and previous table (as in spreadsheets); Ctrl+Tab stays for the choice tabs in dialogs.

8 · A project with no tables

After the last table is closed, the project shows the empty state (DESIGN.md section 5) instead of an empty tab row. The table toolbar hides; New table in the main toolbar, the File menu and Ctrl+Shift+N still work. Import data makes a new table, as now.

The alternative is not to allow closing the last table (its close button hidden). That needs a decision.
